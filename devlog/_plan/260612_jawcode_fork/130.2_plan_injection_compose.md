### Slice B — auth 시딩 브리지 (M2 done ②) — **110과 병행 가능**

cli-jaw 서버 기동 경로에 추가:
```typescript
const storage = await discoverAuthStorage("~/.jwc/agent");   // sdk.ts:409
if (!storage.has("anthropic")) {
  const local = detectClaudeCodeToken();                      // Keychain "Claude Code-credentials"
  if (local) await storage.set("anthropic", { type: "oauth", ...local });
}
```
대안: cli-jaw가 auth-broker 서버 역할 → jwc에 `GJC_AUTH_BROKER_URL` 주입 (브로커 모드).
**검증**: 신규 머신 시나리오 — Claude 로그인만으로 Web UI 1턴 (`auth-broker-import.test.ts` green 유지 + 기동 시딩 신규 테스트).

### Slice C — PABCD boss 하향 주입 (D130-1 단방향)

boss 단계 변경 시 cli-jaw가 `writeNativeWorkflowEnvelopeAtomic(sessionCwd, {...}, { sessionId })` 쓰기 → jwc 세션이 per-turn `readPabcdStateWithFallback` (scoped 우선, shared 폴백 `orchestrate-state.ts:339-350`)으로 자동 수신. 역방향은 `orchestrate verdict` 보고 경로만.
**튜닝 결정**: ① 이중 라벨(`[BOSS — B] · [LOCAL — P]`) vs boss 단독 — `buildPabcdStageContent()`(`pabcd-stage-header.ts:41-68`) 시그니처 변경 여부 ② 주입 시점은 현행 매 턴 파일 재독(1-2KB) 유지.
**검증**: `orchestrate-state.test.ts` boss-inject 케이스 + 단계 도구 게이팅(P/A에서 mutation 차단, 098 §4.2 130.2 항목).
**의존**: Slice A + 110 (sessionId 전달 경로).

### Slice D — 메모리 주입 연결 + consolidation 비활성 (결정 8)

**유일한 jwc 코드 변경**: `runMemoryStartup()` (`memories/index.ts:171-181`)이 Phase1→Phase2를 무조건 실행 — 임베디드 분기 신설.
- 1안(권장): `createAgentSession({ settings })`에 `memory.backend = "off"` 주입 — 코드 변경 0.
- 2안: `runMemoryStartup` 내 `GJC_EMBEDDED` early-return — 주입(`memory_summary.md`)은 유지하고 consolidation만 끊으려면 2안 필요 (1안은 주입까지 꺼지는지 실측 후 선택).
**검증**: 임베디드 세션 consolidation 미실행 로그 + `memory save` → 재시작 시 `memory_summary.md` 주입 확인 + `memory-runtime.test.ts` green. 99.01.03 §0-1 immediate visibility(`refreshBaseSystemPrompt()`) 계약 승계.
