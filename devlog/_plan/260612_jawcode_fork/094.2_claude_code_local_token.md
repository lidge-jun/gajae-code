## 핵심 과제: Keychain 접근

Claude Code는 파일이 아닌 **macOS Keychain**에 토큰 저장.
읽기 방법:

### Option A: `security` CLI (권장)

```typescript
import { execSync } from "node:child_process";

function detectClaudeCodeToken(): OAuthCredentials | null {
  if (process.platform !== "darwin") return null;  // macOS only

  try {
    const raw = execSync(
      'security find-generic-password -s "Claude Code-credentials" -w',
      { encoding: "utf8", timeout: 5000 }
    ).trim();

    const data = JSON.parse(raw);
    const oauth = data?.claudeAiOauth;
    if (!oauth?.accessToken || !oauth?.refreshToken) return null;

    return {
      refresh: oauth.refreshToken,
      access: oauth.accessToken,
      expires: oauth.expiresAt ?? 0,
      // accountId/email: Keychain에 없음 → refreshAnthropicToken()이 반환
    };
  } catch {
    return null;
  }
}
```

### Option B: node-keytar (대안 — 의존성 추가 필요)

```typescript
import keytar from "keytar";
const raw = await keytar.getPassword("Claude Code-credentials", username);
```

> **Option A 채택**: 외부 의존성 없음, macOS 네이티브, sync 가능 (execSync).

### Linux/Windows 대응

| OS | Claude Code 저장소 | 접근 방법 |
|---|---|---|
| macOS | Keychain (`security` CLI) | `security find-generic-password -s ... -w` |
| Linux | `libsecret` / `~/.local/share/keyrings/` | `secret-tool lookup service "Claude Code-credentials"` |
| Windows | Windows Credential Manager | `cmdkey /list` or `dpapi` — 복잡, P3 |

> 초기 구현: **macOS만**. Linux는 후속.

## 구현

### 감지 함수

```typescript
export function detectClaudeCodeToken(): OAuthCredentials | null {
  if (process.platform !== "darwin") return null;

  try {
    const raw = execSync(
      'security find-generic-password -s "Claude Code-credentials" -w',
      { encoding: "utf8", timeout: 5000, stdio: ["pipe", "pipe", "pipe"] }
    ).trim();

    const data = JSON.parse(raw);
    const oauth = data?.claudeAiOauth;
    if (!oauth?.accessToken || !oauth?.refreshToken) return null;

    return {
      refresh: oauth.refreshToken,
      access: oauth.accessToken,
      expires: oauth.expiresAt ?? 0,
    };
  } catch {
    return null;  // Keychain locked, entry missing, etc.
  }
}
```

### login 함수 수정 (`anthropic.ts`)

```typescript
export async function loginAnthropic(ctrl: OAuthController): Promise<OAuthCredentials> {
  // Auto-detect: Claude Code Keychain token
  const local = detectClaudeCodeToken();
  if (local) {
    ctrl.log?.("Found Claude Code token in Keychain, importing automatically");
    if (local.expires < Date.now() + 60_000) {
      try { return await refreshAnthropicToken(local.refresh); }
      catch { /* refresh 실패 → 기존 플로우 */ }
    } else {
      return local;
    }
  }

  // 기존 browser OAuth 플로우
  const flow = new AnthropicOAuthFlow(ctrl);
  return flow.login();
}
```

## 엣지 케이스

| 상황 | 처리 |
|---|---|
| macOS가 아님 (Linux/Windows) | `null` → 기존 플로우 |
| Keychain 잠김 (패스워드 요청) | `execSync` timeout 5s → `null` |
| Claude Code 미설치 / 미로그인 | entry 없음 → `null` |
| `claudeAiOauth` 필드 없음 | `null` |
| 토큰 만료 + refresh 성공 | 새 토큰 반환 (accountId/email 포함) |
| 토큰 만료 + refresh 실패 | `null` → 기존 플로우 |
| Claude Code Pro vs Max | subscriptionType 무관, inference scope만 필요 |

## UX 고려

- `security` CLI 실행 시 macOS가 **Keychain 접근 허용 팝업**을 띄울 수 있음
- 첫 실행에서 "jwc가 Keychain에 접근하려 합니다" → 사용자가 "허용" 필요
- 한 번 허용하면 이후 묻지 않음 (Always Allow 선택 시)
- 팝업이 뜨면 사용자 경험이 약간 어색할 수 있지만, 보안상 올바른 동작
