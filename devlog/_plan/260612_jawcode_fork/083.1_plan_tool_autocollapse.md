# 083.1 — plan: 완료 도구 자동 접힘 (A→B 시 A 한 줄로, 재오픈 가능)

> 상태: 📋 계획 (조사 완료, 구현 ⬜). 소속: 083 ([083_moc_tui_output.md](./083_moc_tui_output.md)).
> 입력: 사용자 "펼쳐지는 건 좋은데 a tool b tool 갔을때 a는 접히고 나중에 열 수 있게 해야지".

## 현재 동작 (코드 사실)

- 도구 펼침은 **전역 단일 플래그** `toolOutputExpanded` (ctrl+o = `app.tools.expand`)로만 제어. 누르면
  **모든** 도구 컴포넌트에 `setExpanded(전역값)` 일괄 적용 (`ui-helpers.ts:157,209,…`, `event-controller.ts:118,371,486`).
- 도구 컴포넌트 상태는 2개뿐: `#expanded`(전체 출력) vs 기본(previewLines 축약). **도구별 "한 줄 요약"
  상태 없음.** → 도구가 여러 개면 각자 preview(헤더+N줄+expand 힌트)가 **세로로 누적**.
- 라이브 생성: `event-controller.ts:472 #handleToolExecutionStart` → `new ToolExecutionComponent(...)` →
  `chatContainer.addChild` + `pendingTools.set(toolCallId, component)`.

## 목표 동작 (Claude Code식)

- **활성/최신 도구만** preview(또는 펼침)로 보이고, 그 이전의 완료 도구는 **한 줄 요약**(아이콘 + 도구명 +
  짧은 인자/상태, 예: `✔ Bash · pwd && ls -la`)으로 접힘.
- 접힌 도구는 **나중에 재오픈** 가능 — 최소한 ctrl+o(전역 펼침)로 전부 펼침. (옵션: 포커스/스크롤 기반 개별 펼침.)

## 설계 (제안)

### A안 (권장·최소 위험): 3-state + "새 도구 시작 시 이전 도구 minimize"
1. `ToolExecutionComponent`에 `#minimized` 상태 + `setMinimized(bool)` 추가. 렌더에서 minimized면
   **헤더 1줄만** 출력(인자/결과 미리보기 생략). `tool-execution.ts:#updateDisplay`에 분기 추가.
2. `event-controller.ts:#handleToolExecutionStart`에서 새 컴포넌트 추가 직전, **직전 활성 도구 컴포넌트를
   `setMinimized(true)`**. "직전 활성"은 `pendingTools`/별도 `#lastToolComponent` 참조로 추적.
3. 전역 `toolOutputExpanded`(ctrl+o)가 true면 minimized 무시하고 전부 펼침 → "나중에 열기" 충족.
   ctrl+o off로 돌아오면 다시 최신만 preview, 나머지 minimized.
4. 정적 재렌더(`ui-helpers.ts`)도 동일 규칙 적용: 마지막 도구만 preview, 그 외 minimized (전역 펼침 아닐 때).
- 손볼 파일: `tool-execution.ts`(+ `bash-execution.ts`/`eval-execution.ts`/`read-tool-group.ts`가 자체
  setExpanded 가지면 minimized도 위임), `event-controller.ts`, `ui-helpers.ts`. 타입: `modes/types.ts` 컨텍스트.

### B안 (대안): 완료 시점 접힘
- `tool_execution_end`에서 해당 도구를 minimize. 단 "마지막 도구도 접힘"이 되어 활성 도구가 안 보일 수 있어,
  "가장 최근 완료 1개는 preview 유지" 규칙 필요 → A안이 더 단순.

### 열린 질문 (구현 전)
1. 재오픈 UX: 전역 ctrl+o만으로 충분한가, 아니면 개별 도구 포커스+Enter로 펼치는 인터랙션 추가?
2. minimized 한 줄 포맷: 도구명 + 인자 요약 어디까지 (bash=명령, read=경로, edit=파일)?
3. 에러 도구는 minimized라도 에러 표식 유지? ([기본값] 에러는 눈에 띄게 — 한 줄에 ✘ + 메시지 첫 줄)
4. 스냅샷 테스트 영향 (tui 896개 중 tool-execution 렌더 스냅샷) — minimized 기본화 시 갱신 범위.

## 검증 (구현 시)

- 단위: 도구 2개 연속 추가 → 첫 도구 `#minimized==true`, 둘째 preview. ctrl+o → 둘 다 펼침.
- e2e: jwc로 도구 여러 개 실행 → 활성만 펼침, 이전은 한 줄, ctrl+o로 전체 펼침 확인.
